## 1. 规模与结构 🟢
- `bms_app` 6,254 / `bms_middleware` 6,432 / `bms_bsp` 3,198 / `bms_config` 663 LOC。
- 单文件规模受控（无超长"上帝文件"——此前 `app_tasks.c` 已拆分重启防护到 `app_reboot_guard.c`）。
- 仅 2 处 `TODO/FIXME` 标记，代码整洁度高。

## 2. 架构与分层 🟢（优秀）
ESP-IDF `REQUIRES` 即依赖真相，构成严格有向无环图：
```
bms_app        REQUIRES bms_config bms_bsp bms_middleware
bms_middleware REQUIRES bms_config bms_bsp
bms_bsp        REQUIRES bms_config
bms_config     (无依赖)
```
无任何向上依赖或循环依赖（`components/bms_bsp/CMakeLists.txt` 仅依赖 `bms_config`）。5 层（main→app→middleware→bsp→driver）落地扎实。

## 3. RTOS / 并发 🟢（良好）
任务优先级（数值大=高）：看门狗 7 > 保护 6 > 采集/告警 5 > SOC 4 > 均衡 3 > 通信 2 > OLED/SD/OTA 1。**安全关键的保护任务优先级最高之一，看门狗最高**，设计正确（`app_tasks.c:1933,1981`、`bms_config.h:223`）。
- **跨核撕裂读已根治**：`sys_params.c` 由 `portMUX` 自旋锁改为"双缓冲 + `xSemaphoreCreateMutex()`"（注释 `sys_params.c:13-23`），读方取稳定活动缓冲，不再撕裂 `float soc_offset`。
- 全部 3 个互斥量均用 `xSemaphoreCreateMutex()`（带优先级继承，`sys_data.c:27`/`sys_mqtt.c:1160`/`sys_params.c:309`），可避免优先级反转。
- 自定义软件看门狗（`task_watchdog`，prio 7）检测任务连续死亡后主动 `esp_restart()`（`app_tasks.c:1898-1900`），与硬件 Task WDT 形成双保险。

## 4. 内存安全 🟢（良好）
- **无周期性任务内堆分配**：`malloc` 仅见于一次性路径——`sys_config_portal.c:328`（WiFi 扫描 `calloc`+`free`）、`app_ota.c:111`（`malloc`+**已做 NULL 检查**:`app_ota.c:112`）、`sys_mqtt.c` 的 `cJSON` 自有分配器 `free`。符合"init 后禁动态分配"的固件铁律。
- `s_irq_flag` 用 `volatile bool` 声明（`bsp_button.c:25`），ISR 写/任务读无编译器缓存风险。

## 5. 错误处理 🟡（中等）
- `esp_*` 调用 178 次，仅 14 次 `ESP_ERROR_CHECK`（7.9%）。**但**抽样可见绝大多数未受检调用为非关键清理/取值：`esp_http_client_close/cleanup`、`esp_ota_mark_app_valid_cancel_rollback`、`esp_timer_get_time`（`app_ota.c`、`app_tasks.c:1543`）。属低风险。
- 建议：对 **init 关键路径**（WiFi/NVS/SPI/GPIO 初始化）的返回做 `ESP_ERROR_CHECK` 或显式降级，而非全量补。
- `configASSERT` 使用 0 次——可适度在参数不变量处加断言。

## 6. ISR 纪律 🟢（优秀）
`button_isr_handler` 为 `IRAM_ATTR`，**仅置 `s_irq_flag=true`，无 LOG/延时/阻塞**（`bsp_button.c:43-47`），业务逻辑延迟到任务。是教科书级 ISR 写法。

## 7. 构建健康 🟢（良好）
- 编译通过，本会话早前确认 `Project build complete`、0 error；`build/` 时间戳 2026-08-14（当日构建）。
- **硬件 Task WDT 已启用**：`CONFIG_ESP_TASK_WDT=y`，超时 10s，双核 idle 任务均受检（`sdkconfig.defaults`）。
- 栈溢出检测 **默认开启**（FreeRTOS CANARY 法，见第 10 维）。

## 8. 测试覆盖 🟡（中等）

## 9. 安全 🟡（中等）
- **无明文密钥泄露**：扫描仅命中测试桩 `test_sys_mqtt.c:286`（测试用 `"ABC123XYZtest"`），非真实凭据。
- **低危**：默认 WiFi 密码 `"1234567890"` 烧录进固件（`bms_config.h:320`，注释"NVS 优先"）。生产应移除编译期默认口令，强制首次配网。

## 10. 运行时安全配置 🟢（良好）
- **FreeRTOS 栈溢出检测默认开启**：ESP-IDF v5.2.7 对 `FREERTOS_CHECK_STACKOVERFLOW` 的 Kconfig 默认值为 **CANARY（method 2）**（`D:/v5.2.7/esp-idf/components/freertos/Kconfig:52`），即 `configCHECK_FOR_STACK_OVERFLOW=2`，每次上下文切换检查栈底金丝雀字节。`sdkconfig.defaults` 未显式设置 ≠ 关闭，而是继承默认值。
- 检测到溢出后调用 `vApplicationStackOverflowHook`（ESP-IDF 提供默认实现），触发 panic/abort，**不会静默内存损坏**。
- 勘误：原评估中 `CONFIG_STACK_CHECK_NONE=y` 表述有误——该名称为 v4 时代遗留，v5.2 对应 `CONFIG_COMPILER_STACK_CHECK` / `CONFIG_COMPILER_STACK_CHECK_MODE_*`，且 GCC 编译期金丝雀与 FreeRTOS 任务栈检查是两套独立机制，前者默认关闭不影响后者。
- 风险放大点（保留）：`task_balance`/`task_alarm` 栈仅 **2,048 B**（`bms_config.h:236,261`），若后续加入 `snprintf`/cJSON 易溢出；`task_comm` 已因 2KB 局部缓冲从 4096 提到 8192（`bms_config.h:240` 注释），说明团队已有栈压力直觉。
- **建议（P1）**：在 `app_main` 后用 `uxTaskGetStackHighWaterMark` 打印各任务高水位，实证确认 2 KB 栈余量；可选将 CANARY 显式写入 `sdkconfig.defaults` 防默认值漂移（文档化动作，非必需）。

## 12. 修复执行记录（2026-08-14）

### 12.1 P1 — 默认 WiFi 口令安全化（`components/bms_config/include/bms_config.h`）
- 新增 `BMS_WIFI_DEFAULTS_ENABLED`（默认 `0` = 生产安全）。
- 默认（`0`）下 `BMS_WIFI_SSID`/`BMS_WIFI_PASS` 均为 `""`；`sys_wifi_init_sta()` 在
  `strlen(wifi_ssid)==0` 时直接返回失败 → 自动进入 AP 配网门户（192.168.4.1），强制现场配网。
- 开发调试可临时置 `1` 启用原默认值（注释明确禁止提交生产分支）。
- 向后兼容：`sys_params.c`、`sys_config_portal.c` 引用的宏名不变，仅取值变为空串。

### 12.2 P1 — 任务栈高水位诊断（`app_tasks.c` / `app_tasks.h` / `main.c`）
- 新增 `app_dump_task_stack_watermarks()`：用 `uxTaskGetSystemState()` 枚举全部任务，
  打印各任务剩余栈空间（字节 = `usStackHighWaterMark × sizeof(StackType_t)`），静态缓冲无运行时堆分配。
- `main.c` 在 `app_tasks_start()` 后延迟 10s 调用一次，实证验证 2KB 小栈（`task_bal`/`task_alarm`）余量。
- 后续可由调试命令周期触发，持续监控栈健康。

### 12.3 保持/防御 — 栈溢出检测显式锁定（`sdkconfig.defaults`）
- 追加 `CONFIG_FREERTOS_CHECK_STACKOVERFLOW_CANARY=y`，显式锁定 method 2（CANARY）栈溢出检测，
  防止 ESP-IDF 默认值漂移；溢出时调用 `vApplicationStackOverflowHook` 触发 panic，不静默损坏。

### 12.4 P2 — init 关键路径错误检查
- `bsp_button.c`：`gpio_install_isr_service()`（容忍 `ESP_ERR_INVALID_STATE`）与
  `gpio_isr_handler_add()` 返回值补检查，失败返回 `BMS_ERR_FAIL`。
- `sys_wifi.c`：`esp_netif_create_default_wifi_sta()`/`ap()` 返回值做 NULL 检查，
  创建失败则中止子系统初始化（下次调用重试），避免后续使用空句柄。

### 12.5 构建验证
- 增量构建（触发 bms_config.h 全量重编）进行中，结果见 `build_verify3.log`。

# Modbus RTU (RS-485) 通信说明书（说明书第 10 篇）

> 目的：BMS 通过 RS-485 总线以 **Modbus RTU Slave（从站）** 方式接入上位机 / PLC / 触摸屏，行业标准实现。
> 依据：Modbus Application Protocol Specification V1.1b3（modbus.org）+ EIA-485 物理层。
> 状态：2026-08-13 已实现并通过固件编译（`HW_ENABLE_RS485=1`）。

---

## 一、物理层（RS-485 / EIA-485）

| 项 | 规格 |
|----|------|
| 收发器 | MAX3485（3.3V，半双工） |
| 接线 | A(+) / B(−) 双绞线，终端电阻 120Ω（总线两端各一） |
| 波特率 | 默认 **9600**（1200~115200 可经保持寄存器 40002 运行时修改） |
| 数据格式 | **8 数据位 / 无校验 / 1 停止位（8N1）** |
| 半双工 | 同一时刻只能一方发送；从站只在响应时占用总线 |

### 1.1 ESP32-S3 引脚（bms_pinmap.h）
| 信号 | GPIO | 说明 |
|------|------|------|
| TX (DI) | **GPIO14** | 接 MAX3485 DI |
| RX (RO) | **GPIO21** | 接 MAX3485 RO |
| DE/RE | **GPIO47** | DE/RE 短接，**高=发送 低=接收** |

> 硬件时序关键：发送前 DE 拉高 → 写 UART → **等待移位寄存器排空**（`uart_wait_tx_done`）→ DE 拉低。
> 若提前拉低 DE，最后一字节会被截断，从站收到 CRC 错误帧（驱动已正确处理）。

### 1.2 设备地址
- 默认从站地址 **1**（`BMS_MODBUS_SLAVE_ADDR`，bms_config.h）
- 可经保持寄存器 **40001** 运行时修改（1~247），NVS 落盘
- 广播地址 **0**：执行但不回复

## 二、协议层（Modbus RTU 帧格式）

### 2.1 RTU 帧
```
[地址(1B)] [功能码(1B)] [数据(NB)] [CRC16 低字节(1B)] [CRC16 高字节(1B)]
```

### 2.2 帧间隔
- 相邻两帧之间必须 ≥ **3.5 字符时间**（9600bps ≈ 4ms）
- 帧内字符间隔必须 **< 1.5 字符时间**，否则从站判为帧错误丢弃
- 固件实现：`BMS_MODBUS_RTU_TIMEOUT_MS=10ms` 判帧

### 2.3 CRC16（MODBUS 多项式 0xA001）
- 初始值 `0xFFFF`，对"地址+功能码+数据"逐字节计算
- **低字节先发**（与多数通用 CRC 相反，注意）
- 校验失败 → 静默丢弃，**不回复**（行业惯例）

## 三、功能码

| 功能码 | 名称 | 用途 | 本机支持 |
|--------|------|------|----------|
| 0x03 | 读保持寄存器 | 读 40001 区（可配置项） | ✅ |
| 0x04 | 读输入寄存器 | 读 30001 区（BMS 实时数据） | ✅ |
| 0x06 | 写单个保持寄存器 | 写 40001 区单寄存器 | ✅ |
| 0x10 | 写多个保持寄存器 | 批量写 40001 区 | ✅ |
| 其他 | — | — | 返回异常码 01 |

### 3.1 请求/响应示例（读输入寄存器 0x04）
**请求**（读 30001 起 2 个寄存器）：
```
01 04 00 00 00 02 <CRC>
```
**响应**（4 字节数据）：
```
01 04 04 <数据1高> <数据1低> <数据2高> <数据2低> <CRC>
```

### 3.2 异常响应
| 异常码 | 含义 | 触发 |
|--------|------|------|
| 0x01 | 非法功能码 | 不支持的 FC |
| 0x02 | 非法数据地址 | 寄存器越界 |
| 0x03 | 非法数据值 | 数量为 0 / 超过 125 等 |
```
异常帧: [地址] [功能码|0x80] [异常码] [CRC]
```

## 四、寄存器表（1 基址，行业惯例）

### 4.1 输入寄存器 30001~30060（功能码 0x04，只读）— BMS 实时数据
| 地址 | 名称 | 单位/格式 | 说明 |
|------|------|-----------|------|
| 30001 | 总电压低 16 位 | mV | `pack.pack_mv & 0xFFFF` |
| 30002 | 总电压高 16 位 | mV | 32S 满充 134V 防溢出，拼 `(高<<16)\|低` |
| 30003 | 总电流 | mA | 有符号 int16（正=放电 负=充电） |
| 30004 | SOC | ×10000 | 0.8563 → 8563 |
| 30005 | SOH | ×10000 | 0.9850 → 9850 |
| 30006 | 最高单体电压 | mV | |
| 30007 | 最低单体电压 | mV | |
| 30008 | 循环次数低 16 位 | 次 | |
| 30009 | 循环次数高 16 位 | 次 | |
| 30010 | 故障掩码 | 位域 | `bms_fault_mask_t` 32 位 |
| 30011 | 充电继电器 | 0/1 | |
| 30012 | 放电继电器 | 0/1 | |
| 30013 | 充电模式 | 枚举 | `bms_charge_mode_e` |
| 30014~30045 | 单体电压 1~32 | mV | 按 `BMS_MAX_CELL_SERIES_NUM` |
| 30046~30077 | 温度 1~32 | 0.1℃ | 与单体电压区段错开 |

### 4.2 保持寄存器 40001~40050（功能码 0x03/0x06/0x10，可读写）— 配置项
| 地址 | 名称 | 单位 | 说明 |
|------|------|------|------|
| 40001 | 从站地址 | 1~247 | 写后即时生效（NVS 落盘） |
| 40002 | 波特率 | bps | 1200~115200，写后即时生效 |
| 40003 | 单体过压保护 | mV | |
| 40004 | 单体欠压保护 | mV | |
| 40005 | 过温保护 | 0.1℃ | |
| 40006 | 低温保护 | 0.1℃ | |
| 40007 | 充电过流保护 | mA | |
| 40008 | 放电过流保护 | mA | |
| 40009 | 过压预警 | mV | |
| 40010 | 欠压预警 | mV | |
| 40011 | 压差预警 | mV | |
| 40012 | 低 SOC 预警 | % | |
| 40013 | 均衡触发阈值 | mV | |
| 40014 | 均衡停止阈值 | mV | |
| 40015 | 串联数 | 串 | |
| 40016 | 容量 | mAh | |
| 40017~40050 | 保留 | — | 读 0，写忽略（可扩展） |

> 保持寄存器写后同步 `sys_params_set()` 落 NVS，**重启不丢失**；保护阈值生效方式与网页/MQTT 下发一致。

## 六、测试方法（验证 Modbus 功能）

### 6.1 硬件准备
```
电脑/USB转485 ──A/B── MAX3485 ── GPIO14/21/47（ESP32-S3）
```
- USB 转 485 模块：A 接 A，B 接 B（不要接反）
- 总线两端各并 120Ω 终端电阻（若仅短距离点对点可省）

### 6.2 用 Modbus Poll（Windows，推荐）
1. 打开 **Modbus Poll** → Connection → 选 COM 口 + 波特率 **9600** + 8N1
2. **Slave ID = 1**
3. 读输入寄存器：Function 04，起始 30001，数量 10 → 应显示总压/电流/SOC 等实时值
4. 读保持寄存器：Function 03，起始 40001 → 显示站地址/波特率/保护阈值
5. 写测试：Function 06，40015（串联数）写 8 → 设备参数更新（重启不丢）

### 6.3 用串口助手手工发帧（快速验证）
读 30001 起 2 个寄存器（Slave=1，FC=04）：
```
请求: 01 04 00 00 00 02 71 CB
响应: 01 04 04 <总压低> <总压高> <电流高> <电流低> <CRC>
```
CRC 工具：https://www.modbustools.com/modbus_crc16.html 或任意在线 CRC16/MODBUS。

### 6.4 串口日志预期（`idf.py monitor`）
```
[BSP_RS485] RS485 初始化完成: UART1 9600-8N1, TX=GPIO14 RX=GPIO21 DE/RE=GPIO47
[SYS_MODBUS] Modbus RTU Slave 就绪: 地址=1 波特率=9600, 保持寄存器 40001~40050, 输入寄存器 30001~30060
```
收到主站请求时无业务日志（正常）；CRC 错误帧会打印 `CRC 校验失败`（WARN）。

### 6.5 常见问题
| 现象 | 原因/处理 |
|------|-----------|
| 无任何响应 | 地址不符 / 波特率不符 / A/B 接反 / DE 未拉低（接收态） |
| 响应乱码/丢尾 | 检查 DE 时序（驱动已处理）；终端电阻缺失 |
| CRC 校验失败告警 | 主站 CRC 算法错误（低字节在前）或总线干扰 |
| 写 40001/40002 后不生效 | 需重新读回确认；波特率修改后主站也要同步改 |

## 七、与现有通信方式的共存

| 通道 | 角色 | 用途 |
|------|------|------|
| RS-485 (Modbus RTU) | 从站 | 上位机/PLC 本地轮询采集与控制 |
| CAN (MCP2515) | 可选 | 车载/储能 CAN 总线 |
| WiFi/MQTT | 客户端 | 华为云 IoTDA + 网页 Dashboard |

三者并行独立，互不干扰（RS485 用 UART1，CAN 用 SPI3，WiFi 用射频）。

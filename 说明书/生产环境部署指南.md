# BMS 仪表盘 · 阿里云 ECS 生产部署指南

> 适用：Ubuntu 22.04 ECS + Cloudflare Tunnel（bms0605.dpdns.org）  
> 目标：全网可访问、仍需登录（方案 A），服务器不直接暴露公网端口

---

## 0. 项目真实拓扑（部署前必读）

| 组件   | 实际情况                                                                                                                                            | 部署含义                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 入口   | `app.py` → `socketio.run(app, host="0.0.0.0", port=5000)`                                                                                       | 监听 5000，由隧道回连           |
| 依赖   | `requirements.txt`：flask / flask-socketio / paho-mqtt / eventlet / python-engineio / python-socketio / huaweicloudsdkcore / huaweicloudsdkiotda | 见下方“依赖说明”               |
| 公网暴露 | `config.yml`：cloudflared 隧道 `bms0605.dpdns.org` → `http://127.0.0.1:5000`                                                                       | **ECS 不需开 80/443/5000** |
| 数据来源 | `iotda_client.py` 出站 HTTPS 拉华为云 IoTDA REST（`*.myhuaweicloud.com:443`）                                                                           | 依赖出方向 443               |
| MQTT | **ECS 上无本地 MQTT broker**（设备上云到华为 IoTDA）                                                                                                         | 不用开 1883/8883           |

**依赖说明（重要）**：`iotda_client.py` 实际用 `requests + 手工 HMAC` 调 IoTDA，**并不使用** `huaweicloudsdkcore / huaweicloudsdkiotda`；`paho-mqtt` 仅 `mqtt_client.py` 用到（`app.py` 未调用它，生产路径走 REST）。所以已生成精简版 **`requirements.prod.txt`**（剔除这三项 + 补上原文件漏写的 `requests`）。2GiB 机器务必用它安装，省内存/磁盘。

**配置文件（重要）**：原 `config.yml` 的 `credentials-file` 是 Windows 路径，但**本地 Windows 实例正在用它跑**，不能改。已另生成服务器专用 **`config.linux.yml`**（路径已改成 `/etc/cloudflared/...json`），部署时直接用这个，本地不受影响。

## 1. 购买前准备（零成本，现在做）

1. **打包代码**：把整个 `tools/dashboard/` 目录带走（U 盘 / 网盘 / git）。包含 `app.py`、`iotda_client.py`、`database.py`、`config.yml`、隧道凭据 json、templates、static。
2. **隧道凭据路径已为你备好**：原 `config.yml` 的 `credentials-file` 是 Windows 路径且本地正在用，不能改。我已另生成服务器专用 **`config.linux.yml`**（路径已改 `/etc/cloudflared/...json`），部署时直接用它，本地不受影响。3. **生成 SSH 密钥对**（在你自己电脑）：


   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/bms_ecs_key
   ```
   公钥 `~/.ssh/bms_ecs_key.pub` 稍后贴到 ECS。
4. **安全组规则**（ECS 控制台创建时配）：
   - 入方向：`TCP 22` 授权对象填你电脑公网 IP（`https://ip.cn` 查）；临时可用 `0.0.0.0/0`
   - 出方向：默认全开（依赖 443/53）
   - **不开** 80 / 443 / 5000 / 1883 / 8883

## 2. 购买 ECS（阿里云控制台）

| 项   | 选择                                                |
| --- | ------------------------------------------------- |
| 地域  | 西南1（成都）                                           |
| 镜像  | Ubuntu 22.04 64位                                  |
| 实例  | 2 vCPU / **2 GiB**（用户已定此规格；务必配合下方 swap + 精简依赖 `requirements.prod.txt`，否则易 OOM） |
| 系统盘 | **ESSD PL0 / 60~80 GiB**（别选 ESSD Entry 40GiB 起步盘） |
| 带宽  | 20 Mbps 按使用流量                                     |
| 付费  | **先按量付费**验证，跑通再转包年包月                              |
| 网络  | 新建 VPC + vSwitch（默认 192.168.0.0/16），安全组挂上面建的      |

> 实例规格/带宽创建后都能升降（带宽秒级），先按建议起步，不够再升。

## 3. 首次登录 + 系统初始化

```bash
# 用密钥登录（换成你的 ECS 公网 IP）
ssh -i ~/.ssh/bms_ecs_key root@<ECS公网IP>
```

```bash
# 1) 建普通用户并授权 sudo
adduser bms --disabled-password
usermod -aG sudo bms
mkdir -p /home/bms/.ssh && cp ~/.ssh/authorized_keys /home/bms/.ssh/ 2>/dev/null
echo "bms ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/bms
chown -R bms:bms /home/bms/.ssh && chmod 700 /home/bms/.ssh

# 2) 部署你的公钥（在你本机执行，把公钥推上去）
# ssh-copy-id -i ~/.ssh/bms_ecs_key.pub bms@<ECS公网IP>
# 或手动：把 bms_ecs_key.pub 内容追加到 /home/bms/.ssh/authorized_keys

# 3) 禁 root 密码登录 + 仅密钥
sed -i 's/^#\?PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart ssh

# 4) 防爆破
apt update && apt install -y fail2ban
systemctl enable --now fail2ban

# 5) 基础工具 + 时区
apt install -y git curl wget unzip htop tmux
timedatectl set-timezone Asia/Shanghai

# 6) 2GiB 机器建 swap 防 OOM（2GiB 跑 Python+SQLite+cloudflared 偏紧）
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## 5. 运行为系统服务（Systemd）

新建 `/etc/systemd/system/bms-dashboard.service`：

```ini
[Unit]
Description=BMS Dashboard (Flask + SocketIO)
After=network.target

[Service]
User=bms
WorkingDirectory=/opt/bms-dashboard
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/bms-dashboard/venv/bin/python app.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bms-dashboard
sudo systemctl status bms-dashboard   # 看是否 active(running)
journalctl -u bms-dashboard -f        # 看日志
```

> 单机先用 `python app.py`（复刻你 Windows 现有入口，风险最低）。小企业要做多 worker，见第 8 节。

## 6. 安装并运行 cloudflared（公网隧道）

```bash
# 下载二进制（Ubuntu x86_64）
wget -O cloudflared https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
sudo install -m 755 cloudflared /usr/local/bin/cloudflared

# 放置隧道凭据 json（和 config.linux.yml 里 credentials-file 指向一致）
sudo mkdir -p /etc/cloudflared
sudo cp 27c0e102-74d6-4b5b-91cd-50b021f09ba4.json /etc/cloudflared/

# 用服务器专用 config.linux.yml 安装为系统服务
sudo cloudflared --config /opt/bms-dashboard/config.linux.yml service install
# 或手动运行：
# sudo cloudflared --config /opt/bms-dashboard/config.linux.yml tunnel run
```

```bash
sudo systemctl enable --now cloudflared
sudo systemctl status cloudflared
```

## 7. 验证清单

1. 浏览器开 `http://<YOUR_ECS_IP>:5000` → 应出现**登录页**（不是 502/超时）。
2. 用账号登录 → 实时数据、曲线、3D 视图正常刷新。
3. `journalctl -u bms-dashboard -f` 无红色报错；`journalctl -u cloudflared -f` 显示 tunnel healthy。
4. 直接访问 `http://<ECS公网IP>:5000` 应**连不上**（安全组已挡）→ 证明服务器未直暴露。

## 8. 小企业上线后加固（按需）

| 项        | 做法                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------- |
| DB 并发    | SQLite 起步；并发上来改 PostgreSQL，或至少开 WAL：`PRAGMA journal_mode=WAL;`                                                    |
| 多 worker | `pip install redis`；`SocketIO(app, message_queue="redis://localhost:6379")`；用 `gunicorn -k eventlet -w 2 app:app` |
| 历史数据     | 按月归档冷数据，避免单库膨胀                                                                                                    |
| 备份       | `crontab` 定时 `cp bms.db bms.db.bak-$(date +%F)` 或 `backup_db.py`（项目已带）                                            |
| 监控       | `htop` 看内存；超 80% 升配                                                                                               |

## 9. 常见排错

- **隧道连上但页面 502**：dashboard 服务没起 → `systemctl restart bms-dashboard`；看日志是否端口被占。
- **cloudflared 报 credentials 找不到**：确认部署用的是 `config.linux.yml`（非 Windows 的 `config.yml`），其 `credentials-file` 应为 `/etc/cloudflared/...json` 且文件已 `cp` 过去。
- **登录后无实时数据**：检查 ECS 出方向 443 是否通（`curl -I https://*.myhuaweicloud.com`）；看 `iotda_client` 日志是否鉴权失败（HK/SK 配置）。
- **内存爆**：2GiB 实例跑 Python+SQLite 易满 → 升 4GiB 或精简依赖。

## 10. 一句话流程

买 ECS（成都/Ubuntu22.04/**2GiB**/60GiB PL0/20M）→ 安全组只开 22 → SSH 初始化（密钥+fail2ban+**2G swap**）→ 传代码（含 config.linux.yml）→ venv 装 **requirements.prod.txt** → systemd 跑 dashboard → 装 cloudflared（用 config.linux.yml）+ 放凭据 → 验证公网登录访问。

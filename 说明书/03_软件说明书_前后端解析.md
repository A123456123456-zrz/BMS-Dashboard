## 2. 数据流（前端视角）

```
┌─ 浏览器 ──────────────────────────────────────────────┐
│ ① SocketIO 长连接 (ws://...): bms_data / bms_fault /  │
│    cmd_resp / mqtt_status 实时推送                     │
│ ② 5s 轮询 /api/status (带3s缓存) → KPI/表格/曲线刷新    │
│ ③ /api/history → 历史曲线 /api/report → 报表           │
│ ④ 命令: /api/cmd、/api/params (带 CSRF token)          │
└──────────────────────────────────────────────────────┘
```

- 推送与轮询双通道，SocketIO 断线时自动降级为纯轮询（稳定性保障）
- 数据去重：同一数据同时来自推送与轮询时只更新一次
- 前端 offline 判定：60s 无新数据判离线（`OFFLINE_MS`），显示灰色断线指示线

## 2.1 双通道架构（2026-08-16：自建 EMQX 为主、华为云为辅）

> 设备同一份属性 JSON **双发**到两个对等 broker；**自建 EMQX 为主（实时），华为云降级为兜底（灾备/影子/规则）**：

```
                        ┌──────── 同一位置：两个对等接入通道 ────────┐
                        │                                            │
 ESP32 ──MQTT 8883 mTLS──▶ 自建 EMQX ──订阅直通──▶ 后端(mqtt_client) ──▶ 前端(实时·主)
   │      (双向证书)         │                          ▲
   │                         │                          │
   └──MQTT 8883──▶ 华为云 IoTDA ──影子/推送──▶ 后端(iotda_client) ──┘  前端(兜底·备)
         (TLS+HMAC)                                                      │
                                              手机App ◀──── 直连 EMQX ──┘
```

| 通道 | 设备接入 | 鉴权 | 后端消费 | 角色 |
|---|---|---|---|---|
| ① 自建 EMQX（主） | `bms/<id>/telemetry`（8883） | mTLS 双向证书（CN=bms01）| `mqtt_client.py` 订阅，毫秒级实时 | **实时主力** |
| ② 华为云（备） | `$oc/devices/...`（8883） | TLS + HMAC-SHA256 动态密码 | `iotda_client.py` 影子轮询 + 推送 | 兜底/影子/规则/告警 |

**主备反转机制（2026-08-16）**：
- 本地腿（EMQX）收到数据 → `mark_local_leg_active()` 刷新活跃时间 + 实时推送前端；
- 华为云腿推送 `bms_data` 前检查 `is_local_leg_active()`——本地腿 30s 内活跃则**跳过实时推送**（数据已由本地腿推过，避免滞后覆盖），但 **DB 入库/规则引擎/告警推送全部保留**；
- 本地腿断线 30s 后，华为云腿自动兜底推送 → 前端不中断。

**关键点**：
- 固件 `sys_mqtt.c` 双 client：`s_client2`（自建 EMQX，mTLS 证书 `mqtt2_client_cert.h/key.h`，URI=`mqtts://<YOUR_ECS_IP>:8883`）+ `s_client`（华为云），`sys_mqtt_report()` 末尾 `publish_json2(json)` 双发同一 JSON；
- EMQX 部署：`deploy/emqx/`（docker-compose + emqx.conf：`verify_peer` + `fail_if_no_peer_cert` + `peer_cert_as_username="cn"` + 文件 ACL 放行 bms01）；
- **后端去重**：`database.insert_data()` 入口按 `(device_id, timestamp)` 内存窗口去重（60s），同一帧只落库一次；
- 命令/回执仍走华为云主通道（第二通道只上报不订阅，避免双端命令竞争）；
- 配置：固件 `bms_config.h` 的 `BMS_MQTT2_*`；后端 `BMS_BRIDGE_MQTT_HOST/PORT/USER/PASS`。

## 3. 后端解析（app.py）

### 3.1 启动流程

```
app.py
 ├─ eventlet.monkey_patch()          ← 必须先调用（否则 WebSocket 频繁断线）
 ├─ 加载 dashboard.env 环境变量       ← AK/SK/密码，环境变量优先
 ├─ SECRET_KEY: 读 .secret_key 文件  ← 持久化，重启不失效（修复 401）
 ├─ Flask app + SocketIO 初始化
 ├─ db.init_db()                      ← 建表 bms_data/audit_log/users
 ├─ IoTDAClient.start()               ← 华为云影子轮询线程
 └─ socketio.run(app, host, 5000)
```

### 3.2 认证与安全

| 机制 | 实现 |
|------|------|
| 登录 | `/login` 表单 → `verify_user`（SHA-256 加盐哈希）→ session |
| 权限 | `login_required` + `role_required`（admin/operator/viewer） |
| CSRF | `csrf_protect` 装饰器（前端带 token） |
| 会话 | `SESSION_PERMANENT=True`，10 分钟超时，`last_activity` 服务端校验 |
| 安全头 | `add_security_headers`（X-Frame-Options 等） |
| 401/403/404/500 | 统一 JSON 错误处理 |

### 3.4 华为云对接（iotda_client.py）

```
IoTDAClient
 ├─ AK/SK 签名（HMAC-SHA256 + HKDF，huaw cloudsdk）
 ├─ _loop 影子轮询: 分级轮询 在线10s / 故障5s / 离线60~900s / 冷启动60s
 ├─ _fetch_shadow → 设备影子 JSON
 ├─ _shadow_to_payload → 影子 → 前端字段（含 last_event_time_ms 年龄判定）
 ├─ publish_cmd → 命令下发（异步 + 结果回读）
 └─ trigger_refresh → 手动刷新信号
```

### 4.2 关键前端行为

- **轮询**: `setInterval` 5s 调 `/api/status`，同时刷新 KPI/表格/曲线（应对 WebSocket 不通的场景）
- **WebSocket**: SocketIO 事件 `bms_data`/`bms_fault`/`cmd_resp`/`mqtt_status`
- **串数适配**: `applySeriesNum(n)` 按后端返回 cells 长度重建表格与曲线
- **传感器未接提示**: `setSensorHint()` —— 设备在线但电压/SOC/温度全 0（LTC6804 未接）时显示横幅
- **曲线横轴智能日期**（2026-08-09 新增）: `fmtAxisSmartTime(d, prevKey)` —— 同一天只显示 `HH:MM:SS`；**跨天自动加 `MM-DD` 前缀（如 `08-10 00:00`），跨月/跨年自然带出月份/年份**，应用于历史曲线、单体电压历史曲线、SOH 24h 分桶
- **初始化防御**（2026-08-09 加固）: init() 中所有数据加载调用（loadParams/loadHistoryChart/loadTrendChart/loadSohTrend/loadDevices/updateCommStatus 等）均包 try-catch——**任何一步失败只打日志，不影响 window 按钮函数暴露**，杜绝"一个错误导致全部按键失效"
- **按钮函数暴露**: HTML 所有 `onclick` 引用的函数必须 `window.xxx = xxx` 暴露（含 🔔 浏览器通知开关 `toggleBrowserNotify`），否则点击报 `is not defined`
- **浏览器通知**（2026-08-09 新增）: 新告警触发 `Notification` 系统弹窗（需授权，顶栏 🔔 按钮开关，localStorage 持久化）
- **PWA**（2026-08-09 新增）: `manifest.json` + favicon + theme-color，可"添加到主屏幕"手机桌面化
- **3D 电池组视图**（2026-08-09 新增）: `renderBattery3D` 纯 CSS/DOM 实现，电芯按串数排成阵列、按电压着色（低红/正常绿/偏高黄/过压橙），支持正/侧/俯三视角切换（`setBattery3DView`），无外部库避免 CDN 风险
- **多设备管理**（2026-08-09 新增）: `/api/devices` 按 `BATTERY_GROUPS` 生成多设备列表（BMS-001/002/003），前端设备下拉切换下发 `switch_battery`，数据隔离按 device_id
- **CSV 导出**: 下载 `/api/export.csv` 文件

### 4.3 告警推送与云端联动（2026-08-09 新增）

| 模块 | 文件 | 行为 |
|------|------|------|
| 企业微信推送 | `alert_push.py` | 故障 0→非0 跳变/设备离线/上线时推送到企业微信群（markdown 卡片），同故障 10min 去重 + 2s 节流（20条/分上限） |

## 6. 前端 ↔ 设备（固件）衔接审查结论（2026-08-09）

对"前端网页 ↔ 后端 ↔ 固件"全链路逐项核查，结论与修复如下：

### 6.1 参数下发链路 ✅ 一致

| 项 | 结论 |
|----|------|
| 参数键 | 前端 `PARAM_META` **41 键全部**被固件 `handle_set_param` 处理（无一下发失败） |
| 固件额外支持 | `soc_gain`/`soc_offset`（前端未配，属扩展项，不影响） |
| 上下限/单位 | 已按 1~32S 修正（总压 max 150000mV），default 与 bms_config.h 一致 |

### 6.2 命令下发链路 ✅ 一致（2026-08-10 D1 已修复）

| 项 | 结论 |
|----|------|
| 后端白名单 | `ALLOWED_CMDS` 小写 13 个（set_charge/set_param/switch_battery...） |
| 固件解析 | `messages/down` 用 `strcmp(cmd, "set_param")` 小写匹配，完全对齐 |
| 下发路径 | `/messages` API（不校验产品模型，避免 IOTDA.014108），双路径兼容 |
| ✅ 修复记录 | **2026-08-10 修复 D1**：控制命令参数丢失（只能关不能开）——后端 `/api/cmd` 顶层参数并入 `paras`（app.py:1216-1227），前端 `sendDeviceCmd` 改发 paras 子对象（app.js:2927），前后端双保险。生效条件：后端重启 + 前端 Ctrl+F5 强刷 |

### 6.3 数据字段链路 ✅ 一致

| 项 | 结论 |
|----|------|
| 字段覆盖 | 前端引用 41 字段：后端 payload 直接提供 32，其余 9 个由 /api/status 扩展响应提供（正常设计） |
| 单位换算 | 电压 mV→V、电流 mA→A、温度 0.1℃→℃、SOC 0~1→% 全链路一致 |

### 6.4 故障映射三方一致 ✅（发现并修复 1 处缺口）

| 项 | 结论 |
|----|------|
| 固件故障码 | 24 个（含 FAULT_NONE=0x0） |
| 推送 FAULT_DEFS | 23 个，全覆盖（仅 0x0 不推，正常） |
| 前端 FAULT_MAP | **修复**：补绝缘 2 个故障码（0x200000 绝缘预警 / 0x400000 绝缘保护）——原缺口导致绝缘故障网页无法显示中文描述 |

### 6.5 功能衔接 ✅（发现并修复 2 处缺口）

| 功能 | 结论 |
|------|------|
| 串数切换 | ✅ 运行时 1~16S（2026-09-07 收口）：前端 `batSeries` 1~16 + 提示文字"1~16" + 下发校验 `<=16` + 设备端 `BMS_HW_MAX_SERIES_NUM=16` 双保险（BQ76952 硬件上限；原 LTC6804 时代的 1~32 已收口）。NVS 持久化，总压基准随串数联动（标称/满充/截止 = 单体 × 串数） |
| SOC 算法 | 前端 5 档 ↔ 固件 soc_algo 0~4 一致（默认 MCC-EKF=3） |
| 均衡控制 | set_balance 真实下发，一致 |
| 绝缘检测 | KPI 字段 + 故障码已补全 |
| 多设备 | 前端切换 ↔ 后端 register_device ↔ 华为云设备 ID 一致 |
| 跑测试 | `python tests/test_dashboard.py` / `python tests/test_ws_stability.py` |
